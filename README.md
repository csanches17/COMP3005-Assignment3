# COMP 3005 - Assignment 3, Q1

## Student Management System

This is a simple Python application that connects to PostgreSQL database and performs CRUD (Create, Read, Update, Delete) operations on student records.

The application uses Psycopg 3 for PostgreSQL connectivity and it has a command-line menu for interacting with the database.

# 1. Technologies
* Python 3
* PostgreSQL
* Psycopg 3
* pgAdmin 4 - db setup and verification

# 2. Project Structure

* app/main.py - Main file containing the CRUD functions and interactive menu
* database/setup.sql - SQL script for creating and populating the students table.
* requirements.txt - Python dependencies - just one in this case
* .gitignore - Files excluded from Git.
* README.md - Instructions for installation, execution, and demonstration.

# 3. Setup and Installation

## 3.1 Download the project
Open a terminal and execute:
git clone https://github.com/csanches17/COMP3005-Assignment3.git
cd COMP3005-Assignment3

Alternatively, you can download the repository as a ZIP file and extract it.

## 3.2 Create and populate the database
1. Start PostgreSQL and open pgAdmin 4.
2. Create a new database named comp3005_assignment3
3. Open the Query Tool for the newly created database.
4. Execute the SQL statements from database/setup.sql
5. Verify the database using:
 * SELECT * FROM students ORDER BY student_id;

The script creates the students table with the following attributes:

Column              Type / Constraint
student_id          INTEGER, autogenerated primary key
first_name          TEXT NOT NULL
last_name           TEXT NOT NULL
email               TEXT NOT NULL UNIQUE
enrollment_date     DATE

It will insert three initial records: John Doe, Jane Smith, and Jim Beam
Make sure to run the setup script on a new, empty database.

## 3.3 Create a Python virtual environment and install dependencies

### Windows (PowerShell)
```bash
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### macOS / Linux
```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## 3.4 Configure Database Connection
By default, app/main.py uses:
* Host: localhost
* Port: 5432
* Database: comp3005_assignment3
* Username: postgres
* Password: requested when the application starts

If you want to use a different configuration, update get_connection() in app/main.py

## 3.5 Running the Application
From the project root directory, execute:
python app/main.py

Enter your PostgreSQL password when prompted.

The application displays the following menu where you can select one of the options:
1. View all students
2. Add a new student
3. Update a student's email
4. Delete a student
5. Exit

4. Implemented Functions

* getAllStudents() - Retrieves all records from the students table and displays their information, ordered by student ID.

* addStudent(first_name, last_name, email, enrollment_date) - Inserts a new student record. PostgreSQL automatically generates the student ID.
The application validates the enrollment date to ensure it follows the YYYY-MM-DD format, represents a valid calendar date, and is not later than the current date. If an invalid date is entered, the applications prompts the user to re-enter the date without restarting the registration process.

* updateStudentEmail(student_id, new_email) - Updates the email address of the student identified by the specific student ID. If not found, it will show a message saying that the student could not be found.

* deleteStudent(student_id) - Deletes the student record identified by the specific student ID. A message will display if the student was deleted.

All CRUD operations use SQL statements with parameters where input values are required. PostgreSQL errors are handled using Psycopg exceptions.

5. Additional notes
* Email address field must be unique.
* Student IDs are generated automatically and are not reused after deletion.
* Enrollment date validation is stricter than the schema provided, which permits NULL dates.
* The application requests database password at runtime. Passwords are not stored.
